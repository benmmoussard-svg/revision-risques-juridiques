# Risques juridiques numériques — résumé complet (texte)

Version texte de la page « Le cours en schémas » : tous les onglets sur une seule page, sans schéma. Sources : 3 PPT de S. Bricca-Druffin (P1 = 5 oct., P2 = 19 oct., P3 = 2 nov. 2026) et TD du 3 nov. Référence `P2·16` = PPT 2, diapo 16. « Hors slides » = vérifié ailleurs, pas dans le cours.

## 0. Les bases

- **Propriété intellectuelle (PI)** : protège les créations de l'esprit. Code de la propriété intellectuelle = **CPI**.
  - **Propriété littéraire et artistique** : protège une **forme**, naît sans dépôt → **droit d'auteur** (roman, musique, **logiciel**) et **droit sui generis** (bases de données).
  - **Propriété industrielle** : protège une **technique** ou un signe, dépôt INPI → **brevet**, marque.
- **Droit d'auteur vs brevet**

| | Droit d'auteur | Brevet |
|---|---|---|
| Protège | la forme (le code) | la solution technique |
| Condition | originalité | nouveauté + activité inventive + application industrielle |
| Naissance | dès la création, gratuit | dépôt payant (INPI, OEB) |
| Durée | 70 ans après la mort | 20 ans |
| Bloque | celui qui copie la forme | tous, même sans copie |

- **Mots clés** : auteur (qui crée) ≠ titulaire (qui détient les droits) · droits moraux (nom, respect ; incessibles, perpétuels) · droits patrimoniaux (exploiter ; cessibles, 70 ans) · licence (droit d'utiliser) ≠ cession (transfert des droits) · contrefaçon (utiliser sans autorisation = délit) · originalité (choix personnels) · CA = cour d'appel, Cass. = Cour de cassation, CJUE = Cour de l'UE, OEB = Office européen des brevets.
- **Délit** : infraction pénale moyenne (contravention < délit < crime), jugée au tribunal correctionnel.
- **Idée-clé** : aucun régime ne protège une **idée**.

## Carte : les 5 risques

1. Le logiciel n'est pas protégé (originalité, dépôt) — P1
2. Se tromper de titulaire (L.113-9) — P2
3. Ignorer l'étendue des droits (L.122-6, contrefaçon) — P2
4. Confondre droit d'auteur et brevet — P3
5. Ignorer le droit des bases de données — P3

## Risque 1 — Qu'est-ce qui est protégé ? (P1)

- Logiciel = programme + documentation + **matériel de conception préparatoire (MCP)** (arrêté 22 déc. 1981). P1·10
- Choix du droit d'auteur : la loi exclut le brevet + influence USA + pratique (plus rapide, moins cher, plus sûr). P1·11
- **L.112-2 13° CPI** : « les logiciels, y compris le matériel de conception préparatoire ». Directive 1991, OMPI art. 4, ADPIC art. 10.1. P1·13-14
- **L.111-1** : droit né du seul fait de la création. P1·17
- **Du plus abstrait au plus concret** :
  - Non protégés (idées) : idée, cahier des charges, fonctionnalités, algorithme, langage (SAS Institute 2012).
  - DA spécial logiciel : MCP, code source, code objet.
  - DA classique, si originaux : interface graphique, documentation, titre (L.112-4 ; CA Paris 2006 Carpoint).
- MCP = documents de travail avant le code (analyses, maquettes, architecture). Le cahier des charges n'en fait pas partie (il exprime les besoins).
- **Originalité** = condition unique : effort personnalisé au-delà d'une logique automatique (Pachot) ; expliquer les choix (Civ. 1re 2012). P1·31
- **Preuve** : ni extraits isolés, ni forcément tout le code → un **échantillon représentatif** avec les choix des devs expliqués (CA Rennes 14 oct. 2025, 40 M de lignes ; CA Bordeaux 18 nov. 2025). P1·32
- **Dépôt = preuve, pas condition** : constitutif (INPI, brevet/marque, crée le droit) · probatoire (APP, e-Soleau 31,04 €, commissaire de justice : date certaine + paternité) · légal (BnF, obligatoire si diffusion sur support, sinon 75 000 €). P1·33-36
- APP = Agence pour la Protection des Programmes (dépôt, constats, séquestre).

## Risque 2 — Qui est titulaire ? (P2)

- Droit commun : le contrat de travail ne transfère rien → cession nécessaire. P2·3
- **L.113-9** : logiciel créé par un salarié **dans ses fonctions** ou **sur instructions** → droits **patrimoniaux** à l'**employeur**, automatiquement, sauf stipulation contraire. Aussi agents publics. Litige : tribunal judiciaire du siège de l'employeur. P2·4
- **L.113-9-1** (ord. 2021) : stagiaire, doctorant → structure d'accueil si convention + contrepartie + autorité d'un responsable + structure **qui fait de la recherche**. P2·5
- **Prestataires** (freelance, ESN, sous-traitant, intérimaire, junior-entreprise) : gardent les droits sauf **cession écrite**. Payer ≠ posséder. P2·6
- Droits **moraux** : toujours à l'auteur (personne physique).
- **Critère = la mission**, pas l'heure ni le lieu (hors slides : TGI Paris 6 mars 2001 ; avocats 2026). Projet lié aux missions → employeur, même le soir chez soi. Vrai projet perso sans lien → salarié.
- **Cas Paul / SOFTPLUS** : Paul code dans ses fonctions → SOFTPLUS titulaire. Partir ne rend pas les droits. Reprendre et améliorer le code = adaptation interdite = contrefaçon.
- Méthode : qualifier le créateur → fonctions/instructions ? → clause contraire ou cession ? → conclure.

## Risque 3 — Quels droits, pour qui ? (P2)

- **Auteur (Paul)** → droits moraux atténués (L.121-7) : garde **paternité** + **respect** (seulement si atteinte à l'honneur) ; perd **repentir** et **retrait** (qui existent pour un roman). P2·11
- **Titulaire (SOFTPLUS, INFOGEST)** → droits patrimoniaux (L.122-6) : 1° **reproduction** même provisoire (installer = reproduire) · 2° **modification** · 3° **distribution**. P2·12
- Limite : **épuisement** — une copie vendue dans l'UE peut être revendue d'occasion (CJUE 2012 UsedSoft c/ Oracle).
- Rémunération : principe proportionnel (L.131-4) ; logiciel : **forfait** permis. P2·14
- **Client (utilisateur légitime)** → 4 droits : utilisation normale + correction d'erreurs · **une** copie de sauvegarde · observer/étudier/tester · **décompiler pour l'interopérabilité**. P2·15
- **Décompilation : 6 conditions** : utilisateur légitime · infos non accessibles · parties strictement nécessaires · seul but interopérabilité · rien aux tiers · pas pour contrefaire. P2·16
- Durée : moraux illimités ; patrimoniaux 70 ans post mortem. P2·17
- **MTP** (mesures techniques de protection : clé, activation, chiffrement) : la loi punit la **diffusion** et la **publicité** des outils de contournement, pas le contournement lui-même (L.122-6-2). P2·18-19
- **Contrefaçon** (L.335-3) : violation de L.122-6. Preuve **par tout moyen** (L.332-4 : saisie-contrefaçon, constat huissier/APP). Le juge regarde les **ressemblances**, pas les différences. P2·20
- **Sanctions** : civiles (dommages-intérêts ; Adobe 289 × 2 299 € = 664 411 €) ; pénales 3 ans + 300 000 €, bande organisée 7 ans + 750 000 €, doublées en récidive. P2·21
- Linagora c/ BlueMind (CA Bordeaux 2025) : un logiciel libre reste protégé.
- **Cas INFOGEST / DISTRIMAX** : licence 10 postes, installé sur 35 de plus → 35 reproductions illicites → contrefaçon par DISTRIMAX. Mots-clés attendus : L.112-2, L.122-6, droit de reproduction, contrat de licence, étendue des droits du licencié.

## Risque 4 — Droit d'auteur ou brevet ? (P3)

- **L.611-10** : nouveauté (absolue) + activité inventive (non évidente pour l'homme du métier) + application industrielle. P3·3-4
- Exclusion : **L.611-10 al. 2 c)** + **art. 52 CBE** : programmes exclus « **en tant que tels** ». P3·5
- On brevète le **procédé technique** (logiciel + matériel), jamais le code seul. Procédé = méthode technique qui agit sur la machine ou le monde réel. P3·6
- OEB IBM 1998 : brevetable si **effet technique**. P3·7
- **COMVIK** (2002) : étape 1 = la revendication cite un élément matériel → caractère technique ; étape 2 = activité inventive jugée sur les seuls traits techniques (maths, méthodes commerciales ignorées). P3·8
- Brevetables : freinage, chiffrement, imagerie médicale, bras robotique. Non : comptabilité, messagerie, vente en ligne, enchères, calcul de pension. P3·9 · France : Cass. 2017, 2023.
- **DA vs brevet** : le DA laisse un concurrent recoder la même fonction ; le brevet bloque la même méthode quel que soit le code (mais pas une méthode différente au même résultat). P3·11
- **3 pièges du dépôt** : rejet (pas d'effet technique) · publié sans être délivré (invention révélée sans protection) · pas de recherche d'antériorité (existe déjà → brevet nul). P3·12
- **Checklist entreprise (8)** : lister · choisir (brevet/DA/secret) · vérifier la titularité · chercher les antériorités (INPI, OEB, OMPI) · rédiger la demande avec un conseil en propriété industrielle en visant l'effet technique · dater (APP, e-Soleau) · budgéter les annuités (chaque année jusqu'à 20 ans) · archiver les contrats. P3·13
- **Cas MEDTECH** : « nouveau donc brevetable » → faux raisonnement (3 conditions), mais brevet possible : effet technique sur l'appareil médical.

## Risque 5 — Bases de données (P3)

- **Personnages du TD** : THEGOODCORNER = nom inventé pour Leboncoin (victime) ; FUNCAR = le concurrent qui copie.
- **Définition L.112-3** : éléments **I**ndépendants, **R**angés avec méthode, **A**ccessibles un par un (« I-R-A »). P3·17
- **Armoire + fiches** : l'armoire (architecture) → **droit d'auteur** si rangement original, titulaire l'auteur, **pas de dévolution à l'employeur**, 70 ans (contre-exemple Football Dataco 2012). Les fiches (contenu) → **droit sui generis** (L.341-1), au **producteur** (qui paie et prend le risque), si **investissement substantiel**, **15 ans**. Cumulables. P3·18-26
- **Sui generis** = « de son propre genre » : droit spécial qui récompense celui qui a payé pour rassembler les données (image : une collection de timbres).
- **Investissement qui compte** : obtenir (collecter des données existantes), vérifier (modération), présenter (catégories). **Créer** les données ne compte pas (BHB 2004). P3·22
- **Ryanair 2015** ✗ : base reconnue, mais coûts de billetterie exclus → pas substantiel. **Leboncoin 2022** ✓ : pub, stockage, modération, catégories → protégé ; reprise de la rubrique immobilier = partie qualitativement substantielle. P3·23-28
- **L.342-1** : interdire l'**extraction** (copier sur un autre support) et la **réutilisation** (mettre à disposition du public) d'une partie substantielle (quantité OU qualité). **L.342-2** : aussi les petites parties répétées et systématiques (robot qui copie 10 annonces par jour). P3·27
- **CV Online** (CJUE 2021, repris Cass. 2025) : prouver en plus que la copie menace la rentabilité de l'investissement. CV-Online = un site letton d'offres d'emploi. P3·29
- **Exceptions L.342-3** : partie non substantielle, usage privé, handicap, enseignement, recherche, bibliothèques, TDM. P3·30
- **Fouille de données (TDM, L.122-5-3)** : II recherche publique → toujours permis ; III toute autre finalité (entreprise, IA) → permis sauf opt-out lisible par machine. P3·31-34
- Sanctions : 3 ans + 300 000 €, dommages-intérêts. P3·35
- **Réponse FUNCAR** : 1. base (L.112-3) → 2. investissement substantiel (L.341-1) → 3. extraction et réutilisation (L.342-1) → 4. illicite. « Accessible en ligne ≠ libre de copie ».

| Cas | Notion décisive | Réponse |

Méthode : faits → problème de droit → règle (article + jurisprudence) → application → conclusion.

## Pièges

- Le salarié auteur garde les droits : **faux** pour le logiciel (L.113-9), **vrai** pour l'architecture d'une base.
- Un freelance payé cède ses droits : **faux**, il faut une cession écrite.
- Mêmes fonctionnalités = contrefaçon : **faux** (SAS 2012).
- Logiciel jamais brevetable : **faux**, exclu seulement « en tant que tel ».
- Accessible en ligne = libre : **faux** (L.342-1).
- Créer les données = investissement : **faux** (BHB, Ryanair).
- Le juge regarde les différences : **faux**, les ressemblances.
